# Узлы VPN

## Идея

Выбрать один постоянный узел выхода сервера по статистике за неделю, а не по впечатлению за один вечер, и дальше никуда не прыгать. Поводом стал Стокгольм 9 октября 2026: долго работал, а при строгой проверке оказался полуживым.

Устроено по образцу сбора данных DASH ([[projects/dash-trading/README|Торговля DASH]]): отдельная служба сама копит замеры, разбор — по накопленным данным.

## Что меряем

- Каждый узел — отдельной пробной копией туннеля на свободном порту. Рабочий выход и страж не трогаются.
- Пять служб, три круга подряд (15 запросов на узел): нейросеть (`api.anthropic.com`), Telegram (`api.telegram.org`), Google и YouTube (`generate_204`), Cloudflare (`cdn-cgi/trace`).
- По каждому запросу: ответила ли служба и за сколько. По узлу: адрес и страна выхода.

## Какие узлы

Все узлы подписки (около 50), кроме Москвы и стран вне списка, где Anthropic разрешает работу. Список стран сверять со страницей Anthropic на момент прогона.

## Этапы

1. **Разовый прогон всех подходящих узлов.** Завершён 9 октября; таблица показывает, какие узлы проходят всё, работают с перебоями или не работают.
2. **Неделя наблюдения.** Запущена по «запускай» Егора в 19:11, окно 9 октября 19:17 — 16 октября 19:17 МСК. Раз в 3 часа, первый замер сразу. Служба ничего не переключает и в чат по ходу недели не пишет; проверяет доступность сервера Anthropic без ключа, не запускает модель.
3. **Недельные итоги** — одно сообщение после последнего замера. По каждому узлу и каждой из пяти служб: число удачных замеров, перебоев и отказов; самый долгий перерыв; время ответа. Плюс: менялись ли адрес и страна выхода. После доставки итога таймер выключается.

## Решения

- Основной узел выбирать по нейросети и Telegram (как у стража); Google, YouTube и Cloudflare — чтобы выбрать среди равных (YouTube нужен для роликов Нейта).
- 9 октября 2026, 17:56 — отдельный проект, по образцу сбора данных для трейдинга.
- После выбора страж переключается на выбранный узел один раз; очередь запасных собирается по тем же данным.

## Ограничения

Замер показывает работу узла именно с нашего сервера. Неделя говорит только о том, как узлы работали в эту неделю, гарантий на будущее не даёт.

## Связи

- Страж выхода: `docs/vpn-guard.md`, `deploy/vpn-guard/`; та же пробная проверка — `sudo vpn-guard probe`.
- Ссылка подписки — секрет (`/etc/vpn-guard/subscription`), в проект не копировать.
- Программа замеров: `deploy/vpn-nodes/vpn-nodes` (образец), на сервере `/usr/local/sbin/vpn-nodes` (root), установка — `sudo sh deploy/vpn-nodes/install.sh`. Разовый прогон: `sudo vpn-nodes run [--table ИМЯ.md]`. Подписку, разбор узлов и пробный Xray берёт у установленного стража; страж, его блокировку и рабочий выход не трогает.
- Неделя наблюдения: `sudo vpn-nodes week` — записывает начало и конец недели в `/var/lib/vpn-nodes/week.json`, включает `vpn-nodes.timer` (00, 03, 06 … 21 по Москве) и сразу делает первый замер. Каждый замер переписывает `Последний прогон.md`. После последнего замера недели программа пишет `Итоги недели <период>.md` и отправляет Егору одно сообщение (с записью в историю переписки), затем выключает таймер. Не ушло — повторит в следующий слот таймера. Промежуточные итоги в тот же файл без отправки: `sudo vpn-nodes report`. Ход замера: `journalctl -u vpn-nodes.service`.
- Данные: `замеры/журнал.jsonl` — строка на узел за прогон (коды и время каждой службы по кругам, адрес и страна выхода по кругам); таблица прогона — в корне папки.
- Провайдер раздаёт адреса выхода из пула: у одного узла между кругами адрес может меняться (Осло, Амстердам — 2 адреса за 3 круга), страна при этом та же.
