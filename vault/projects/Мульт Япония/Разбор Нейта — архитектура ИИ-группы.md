# Как Нейт организует работу нескольких ИИ-агентов

Разбор для проекта «Мульт Япония» · 20 октября 2026 года

## Главный результат

У Нейта есть три разных подхода, которые нельзя объединять в одну якобы готовую архитектуру: встроенная делегация Codex, совет подагентов Claude Code и общая платформа Kylon. Запуск помощников прямо в Codex он действительно показывает. Свой диспетчер на Python для этого примера не нужен.

К постоянной творческой группе с перепиской участников ближе Kylon. К работе через одного руководителя в Codex — его встроенные подагенты. Roast Room — совет для обсуждения решений: участники возвращают позиции председателю, а не ведут производство каждый в своей должности.

Егор уже определил должности и обязанности. Этот разбор касается технического устройства, а не придумывания ему новых ролей. Выбор платформы и сборка системы ещё не поручены.

| Подход Нейта | Что запускает исполнителей | Как передаётся работа | Где работает пользователь |
|---|---|---|---|
| Встроенная делегация Codex | Основная сессия через встроенный механизм | Отдельные ветки; результат руководителю; показана пересылка между задачами | Codex |
| Совет Roast Room | Навык `/roast-room` вызывает подагентов Claude Code | Председатель сохраняет ответы и передаёт файлы следующему кругу | Claude Code; дополнительный экран необязателен |
| Общая среда Kylon | Готовая платформа и её шлюз; либо облачный исполнитель | Комнаты, ветки, адресные сообщения, общие материалы | Kylon |

## 1. Что уже показано непосредственно в Codex

Источник: [«Все понятия Codex простыми словами»](https://www.youtube.com/watch?v=DFlELTiSPk8), опубликован 3 октября 2026, 34:33.

### Запуск

В [28:18–30:11](https://www.youtube.com/watch?v=DFlELTiSPk8&t=1698s) Нейт обычным текстовым поручением просит основную сессию распределить исследование между помощниками. Основная сессия использует Astra, для исполнителей запрошена другая модель. Возникают пять видимых участников: новости X, обсуждения X, тенденции YouTube, комментарии аудитории и официальные объявления. На экране основной ответ прямо сообщает о пяти отдельных исполнителях.

Схема показанного процесса:

```text
Нейт → основная сессия Codex
                 ↓ встроенная делегация
          пять отдельных подагентов
                 ↓ ответы
          основная сессия → Нейт
```

Это не пять вручную открытых чатов и не наша программа, которая обращается к `app-server`. Механизм запуска уже находится внутри показанного Codex. Внутренние программные вызовы этого механизма в ролике не раскрываются.

### Передача между задачами

В [32:13–34:19](https://www.youtube.com/watch?v=DFlELTiSPk8&t=1933s) Нейт голосом просит создать отдельную ветку для обложки и отправить результат в исследовательскую ветку. В 33:53 видна пометка о сообщении из другой задачи, а в 34:08 — сама картинка в целевой ветке. Это подтверждает передачу результата между задачами в показанном окружении. Это ещё не демонстрация постоянной переписки всех исполнителей между собой.

### Память и границы

Проект опирается на файлы и инструкции `AGENTS.md`; исполнители имеют отдельные видимые рабочие ветки. Однако ролик не доказывает, что эти пять исследователей сохраняются как постоянные должности, автоматически продолжают личную историю после каждого запуска и имеют разные права на файлы.

Для «Мульт Япония» здесь подтверждён принцип «один руководитель в Codex → несколько исполнителей → сбор результата». Постоянная киногруппа, очередность производства и запрет изменять чужие материалы остаются отдельными вопросами.

Пятичасовой [курс Codex](https://www.youtube.com/watch?v=X-pbJWKmwi0) содержит практически тот же демонстрационный блок с 33:24. Его нельзя считать вторым независимым испытанием.

## 2. Как устроен совет Roast Room

Источник: [«Я создал совет ИИ-консультантов»](https://www.youtube.com/watch?v=nRXHWckVxoM), опубликован 13 октября 2026, 14:44. Дополнительно прочитаны публичные файлы автора на площадке GitHub: репозиторий [nateherkai/roast-room](https://github.com/nateherkai/roast-room).

GitHub здесь — площадка; репозиторий — набор файлов программы и инструкций Нейта; Roast Room — сам инструмент. Наш проект с материалами Нейта хранит разборы этих источников, а не является программой Roast Room.

### Запуск и три круга

Пользователь вводит `/roast-room` в Claude Code. Основной Claude Code становится председателем. В [02:35–02:42](https://www.youtube.com/watch?v=nRXHWckVxoM&t=155s) Нейт подчёркивает: использованы подагенты, а не Agent Teams. Участники возвращают ответы председателю.

Проверенный [SKILL.md](https://github.com/nateherkai/roast-room/blob/main/.claude/skills/roast-room/SKILL.md) задаёт реальную последовательность:

1. Подготовить исходное задание `brief.md` и состав участников.
2. Одним сообщением параллельно вызвать нужных подагентов: `subagent_type: council-<seat>`, `run_in_background: false`.
3. Сохранить ответы в `round-1.md`, выделить разногласия.
4. Заново вызвать участников для обсуждения первого круга; сохранить `round-2.md` и проект решения.
5. Ещё раз вызвать участников для голосования; сохранить `round-3.md` и окончательный вывод.

Полный состав из семи участников означает 21 вызов за три круга. Это семь определений ролей с повторными запусками, а не семь непрерывно живущих сессий.

```text
Пользователь → Claude Code / председатель
                         ↓ навык /roast-room
                 семь подагентов, круг 1
                         ↓ ответы в файле
                 семь новых вызовов, круг 2
                         ↓ проект решения
                 семь новых вызовов, круг 3
                         ↓
                 председатель → итог
```

### Как они обмениваются замечаниями

В [шаблонах запросов](https://github.com/nateherkai/roast-room/blob/main/.claude/skills/roast-room/references/round-prompts.md) передача состояния задана явно:

| Круг | Что получает роль |
|---|---|
| 1 | Собственную базу знаний и общее исходное задание |
| 2 | Собственную базу, исходное задание и ответы первого круга |
| 3 | Исходное задание, свою часть второго круга и проект общего решения |

Возражение одному из коллег существует как текст в возвращённой карточке. Прямого канала сообщений между подагентами нет: председатель собирает ответы и выдаёт материалы следующему вызову.

### Роли, память и права

Семь ролей описаны в `.claude/agents/council-*.md`. У каждой есть отдельная база в `.claude/skills/roast-room/brains/<имя>/`: короткая памятка, принципы, схемы принятия решений, позиции, истории и источники. Обычно сначала читается `_hot.md`, затем подходящие тематические файлы.

У всех семи проверенных определений заданы только `Read, Grep, Glob` и `maxTurns: 12`; пример — [роль Безоса](https://github.com/nateherkai/roast-room/blob/main/.claude/agents/council-bezos.md). Эти участники читают и оценивают, а запись итогов выполняет председатель. Доступ на чтение при этом не ограничен технически единственной папкой конкретной роли.

Состояние сохраняется в файлах сеанса: задание, раунды, разногласия, проект решения и окончательный отчёт. Личную долговременную историю каждого участника схема не требует: очередной вызов восстанавливает контекст из выданных материалов.

Есть два запасных режима. Если специальная роль не зарегистрирована, запускается общий подагент с текстовым запретом записывать файлы; равенство инструментальных ограничений в этом режиме не гарантируется. Если делегация недоступна вообще, один агент последовательно разыгрывает роли — отдельных контекстов тогда нет.

### Что делает красивый экран

Наглядная страница на `localhost:4730` по умолчанию читает файлы сеанса и показывает ход или повтор обсуждения. По проверенному [app/server.mjs](https://github.com/nateherkai/roast-room/blob/main/app/server.mjs) она не является обязательным диспетчером запросов к модели. Отдельный режим через Anthropic API существует, но это другой способ запуска.

### Что это даёт киногруппе

Хорошо подтверждены отдельные инструкции, тематические знания, вызов ролей и обмен замечаниями через председателя. Однако готовые участники Roast Room не производят сценарий, рисунки или видео: у них даже не предусмотрены инструменты записи и генерации. Это совет для разбора решения. Механизм применим как образец обсуждения, но готовность производственной студии и перенос в ChatGPT/Codex не доказаны.

Код прочитан с текущей ветки `main` 20 октября. Его точное совпадение с версией, снятой в ролике, не установлено. Собственного запуска Roast Room в рамках разбора не было.

## 3. Kylon: общая среда людей и агентов

Источник: [«ИИ-агенты теперь работают сообща»](https://www.youtube.com/watch?v=KZiF2J83zaY), опубликован 15 октября 2026, 22:24. Это спонсированный Kylon ролик. Устройство дополнительно сверено с собственными страницами и документацией сервиса.

### Какие части физически существуют

У Нейта работает готовая платформа Kylon: рабочая среда, комнаты по направлениям, отдельные обсуждения задач, люди и агенты. В составе видны Herk, Claude Code и Codex. К комнатам относятся файлы, приложения и автоматизации.

```text
Нейт и коллеги ↔ интерфейс Kylon
                       ↕
            комнаты, ветки, файлы, задания
                       ↕
                 агенты комнаты
           ┌───────────┼────────────┐
           ↓           ↓            ↓
     агент Kylon   Codex в      Kylon CLI
       в облаке   облаке Kylon  на компьютере
                                    ↕
                              Codex / Claude Code
                                    ↕
                               облачная модель
```

Это несколько способов исполнения, а не обязательная цепочка через все блоки сразу.

### Что именно запускает подключённый Codex

В [15:16–15:46](https://www.youtube.com/watch?v=KZiF2J83zaY&t=916s) Нейт копирует предложенное Kylon задание в Claude Code и подключает компьютер. Точный кадр 15:23 сообщает об установке Kylon CLI, настройках в `~/.kylon` и регистрации фоновой службы.

Текущая [документация CLI](https://docs.kylon.io/cli/overview) уточняет: фоновый шлюз получает задачи из Kylon, использует подключённые инструменты и возобновляет сессии исполнителя. Команды `kylon workspace ...` дают доступ к комнатам, обсуждениям, файлам и другим материалам. Таким образом, готовую программу связи поставляет Kylon; мы её заново не пишем.

В 20:15 профиль реально подключённого Nate Codex показывает `codex-cli 0.162.0-alpha.2`, `Kylon CLI 0.7.9`, компьютер `Nate-World`, модель `GPT-6.1-Sol`, мышление `High`. Это версии в записи, а не рекомендация установить именно их сейчас.

Если исполнитель находится на личном компьютере, тот должен работать и иметь сеть. Это и слова Нейта, и текущая [инструкция подключения](https://docs.kylon.io/agents/bring-your-own-agent). Вычисления модели при этом не становятся вычислениями домашней видеокарты.

### Общение и сохранение работы

В [00:45–01:05](https://www.youtube.com/watch?v=KZiF2J83zaY&t=45s) показана переписка Herk и Nate Claude о доработке панели. В задании есть предварительный просмотр, согласование публикации Нейтом и требование не повторять уже выполненные записи. В ответе Claude сообщает о сделанной доработке и проверках. Это видимые задание и отчёт; сами тесты в ролике не воспроизведены.

В [05:30](https://www.youtube.com/watch?v=KZiF2J83zaY&t=330s) показана комната, где работают Нейт, его Codex и Claude Code. В [08:01–08:43](https://www.youtube.com/watch?v=KZiF2J83zaY&t=481s) — отдельные обсуждения задач: закрытую ветку можно убрать из текущего вида, но история остаётся доступной. Видны также адресные обращения и возможность личного разговора с агентом при наличии доступа.

Внутренние форматы сообщений, очередь занятого агента и алгоритм маршрутизации Нейт не раскрывает. Участие разных агентов в комнате также не доказывает, что у каждой будущей кинодолжности уже настроена постоянная независимая история и собственное файловое пространство.

### Какие ограничения доступа действительно есть

На экране создания новый агент обозначен приватным и без доступа к существующим комнатам. В 20:44 профиль Codex коллеги закрыт для Нейта. [Документация доступа](https://docs.kylon.io/agents/access) подтверждает два отдельных решения: кто может обращаться к агенту и в какие комнаты он добавлен. Агент также может получить доступ к другому агенту.

Это реальные границы, но они не равны запрету сценаристу менять рисунки художника. Более того, текущая инструкция подключения прямо указывает: компьютерный агент работает от имени пользователя операционной системы и использует доступные этому пользователю файлы и инструменты; локальных запросов разрешения во время заданий Codex/Claude Code не ожидается. Поэтому общая учётная запись компьютера сама по себе не разделяет должностные области записи.

### Где здесь ChatGPT

В [14:19–14:29](https://www.youtube.com/watch?v=KZiF2J83zaY&t=859s) показан отдельный вариант Codex в облаке Kylon с подключением аккаунта ChatGPT. Его настройку и длительную работу Нейт в этом фрагменте не выполняет.

[Текущая инструкция Kylon](https://docs.kylon.io/tutorials/use-your-chatgpt-subscription) описывает этот вариант: Codex работает на облачном компьютере Kylon, использует подписку ChatGPT, не видит файлы личного компьютера и просыпается по новому сообщению. Возможность включается отдельно для рабочей среды; её наличие в любой новой учётной записи не гарантируется.

Это подключение аккаунта для Codex. Обычный чат ChatGPT как отдельный главный пульт Нейт здесь не показывает. Пользовательский интерфейс совместной работы — Kylon.

### Восстановление и практическая граница

По текущей документации шлюз переподключается после возвращения компьютера в сеть и поддерживает возобновление сессий. Но в ролике не испытаны обрыв активной задачи, частично выполненная публикация, восстановление очереди и отсутствие повторов после сбоя. Наличие этих гарантий нельзя выводить из одного успешного примера.

Kylon ближе остальных рассмотренных решений к общей студии с адресной перепиской. Готовую цепочку кинопроизводства и строгие права на материалы каждой должности Нейт не продемонстрировал.

Особенно полезен участок [13:46–16:24](https://www.youtube.com/watch?v=NyfYxpXiw_0&t=826s). При этом рабочий компьютер и файлы общие. Это другая платформа; её функции нельзя автоматически переносить на Codex. Нужных кадров старой записи в архиве нет, поэтому здесь повторно проверен текст с таймкодами, а не экран.

[«Как создавать навыки Codex»](https://www.youtube.com/watch?v=9KOtMsZ9I28), 19 сентября: в [03:42–06:28](https://www.youtube.com/watch?v=9KOtMsZ9I28&t=222s) Нейт предлагает один конкретный процесс на навык, затем связывать процессы последовательно. Навык с названием должности сам по себе не создаёт сотрудника с отдельной памятью и правами.

[«Превращаем Claude в маркетинговую команду»](https://www.youtube.com/watch?v=yCACmFTiCto), 21 августа: показаны общие материалы, навыки и генерация через Higgsfield. В [31:07–34:30](https://www.youtube.com/watch?v=yCACmFTiCto&t=1867s) есть персонажи, раскадровки, создание видео и отбраковка результата. Но это работа одного агента с инструментами; слово «команда» в названии не доказывает существование отдельных должностных исполнителей. Экран этих старых участков повторно не проверялся из-за отсутствующих кадров.

## 5. Что можно заключить для «Мульт Япония»

| Требование Егора | Codex у Нейта | Roast Room | Kylon у Нейта |
|---|---|---|---|
| Запуск нескольких исполнителей | Показан встроенный запуск | Проверены вызовы из навыка | Показана работа разных агентов; подключение через готовый шлюз |
| Разделённые роли | Отдельные исследовательские задачи | Файлы ролей и базы знаний | Специальности и профили |
| Обмен результатами | Возврат руководителю; пересылка между задачами | Через председателя и файлы | Адресная переписка в общей среде |
| Сохранённая работа | Проектные файлы и видимые ветки | Файлы всех кругов и итог | Комнаты, ветки и материалы; внешний источник можно сохранить |
| Запрет менять чужие материалы | Не продемонстрирован | Советники ограничены чтением; председатель пишет | Права на агента/комнаты есть; изоляция должностных файлов не показана |
| Готовая киногруппа | Нет | Нет | Нет |
| Обычный ChatGPT как главный пульт | Такой связки не показано | Не показано | Не показано; аккаунт ChatGPT используется для входа Codex |

Возможные основы различаются по способу работы: один разговор с руководителем — ближе к показанному Codex; общие комнаты и прямая переписка участников — ближе к Kylon; обсуждение спорных решений — к Roast Room. Это вывод разбора, а не готовая реализация для Егора.

Пока нельзя утверждать, что одна из них полностью обеспечивает все требования киногруппы. Зато уже можно исключить прежнее предположение, будто для самого запуска нескольких помощников обязательно сначала писать свой Python-диспетчер, очередь SQLite и связь ChatGPT через MCP. В примерах Нейта используются уже существующие механизмы.

## 6. Что именно проверено

Повторно прочитаны полные тексты двух основных роликов — о Roast Room и Kylon; сверены их субтитры и ключевые кадры. Для Kylon дополнительно извлечены точные кадры из сохранённого видео, где видны фоновая служба, способ подключения и версия исполнителя. Для Codex проверены соответствующие участки текста и полные кадры запуска и передачи результата.

Дополнительно прочитаны опубликованные файлы Roast Room и собственная документация Kylon. Это анализ исходников и демонстраций. Установка, запуск на нашей учётной записи, испытание сбоев, проверка производственной киногруппы и расходов не проводились. Тарифы здесь не сравниваются.

Предыдущая схема помощника с Python, SQLite, `app-server` и MCP была самостоятельным предложением. Она не является схемой Нейта и не имеет статуса проверенного решения. Настоящий разбор сохраняет эту границу.
