Понял, пока обсуждаем устройство системы — маршруты и даты не нужны.

Я бы сделал <b>небольшой скрипт на Python на сервере</b>, а управление и уведомления — через этот Telegram-бот. Внутри три части:

• <b>Поиск:</b> по расписанию получает предложения, сохраняет историю цен. Учитывает багаж, пересадки и итоговую стоимость, чтобы сравнивать сопоставимые билеты.
• <b>Отбор:</b> замечает подходящую цену или её снижение, присылает вариант без повторных уведомлений об одном и том же.
• <b>Бронирование:</b> повторно проверяет цену и наличие, затем пытается оформить бронь — по твоей кнопке либо автоматически в заранее заданных пределах.

<b>Главная развилка — источник данных.</b> Предпочтителен официальный API для поиска и оформления. Другой путь — автоматизация сайта через браузер, но она требует больше обслуживания: изменения страниц, капчи и вход в аккаунт могут прерывать работу. Конкретные возможности нужно проверять у выбранного сервиса.

🎫 Бронь без оплаты — отдельная возможность продавца. Система должна считать успехом только подтверждённую бронь с номером и сроком оплаты. Открытая страница оформления сама по себе ничего не фиксирует.

Поэтому разумный концепт: <b>единый мониторинг и отдельный модуль бронирования под конкретного продавца</b>. Сначала можно запустить поиск и уведомления, затем подключить оформление. Нейросеть для постоянной проверки цен не нужна — обычный скрипт будет предсказуемее.
