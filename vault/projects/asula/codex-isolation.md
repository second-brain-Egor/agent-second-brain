# Кодекс на рабочей машине — закрытый контур

Выводы обсуждения 2026-06-16. Контекст: планируется поставить Кодекс на отдельную машину для работы в рамках АСУЛА. На диске есть чувствительная и общая информация. Задача — чтобы чувствительная информация вообще не попадала в Кодекс.

## Машина

Ноутбук: Ryzen 7 7840HS, встроенная графика Radeon 780M, 32 ГБ ОЗУ. Дискретной видеокарты нет — всё, что упирается в видеопамять, делит общую оперативку.

Что реально пойдёт локально (Ollama):
- 7–8B (Llama 3.1 8B, Qwen 2.5 7B, Mistral 7B) — комфортно, рабочая лошадка для документов.
- 13–14B (Qwen 2.5 14B) — нормально, медленнее.
- 30–32B в квантизации — влезет, но медленно, для пакетной обработки.
- 70B и выше — не сюда.

Распознавание речи: Whisper (faster-whisper) — локально, идёт уверенно.
Семантический поиск по документам: локальные эмбеддинги (nomic-embed, bge-m3) + векторная база (Chroma, Qdrant) — целиком на машине.

## Главный принцип изоляции

Не «прятать» чувствительное от Кодекса, а давать Кодексу доступ только к разрешённой папке. Всё остальное он физически не видит. Изоляция «по умолчанию ничего», а не «по умолчанию всё, кроме секретного».

## Вариант 1 — Docker (рекомендуется)

Кодекс запускается внутри контейнера, монтируется ровно одна папка с общей информацией:
- `docker run -v C:\codex-work:/work ...` — внутри виден только `/work`, остальной диск недоступен в принципе.
- Чувствительные данные держатся вне этой папки — Кодекс до них не дотянется.
- Контейнер легко прибить и пересоздать, систему не пачкает.

Под Windows 11 Pro — WSL2 + Docker Desktop, либо чистый WSL2 с Кодексом внутри.

## Вариант 2 — отдельный пользователь Windows

Без Докера: отдельная учётка для Кодекса. Чувствительные папки — у основной учётки с NTFS-правами «запретить доступ» для учётки Кодекса. Слабее: одна ошибка в правах — и доступ открыт.

## Сеть — важнее, чем кажется

Закрыть от чтения мало: если данные попали в контекст, они уйдут на сервер модели. Поэтому:
- чувствительное никогда не кладётся в рабочую папку Кодекса, даже временно;
- смысловую обработку чувствительного выносить на локальную модель (Ollama на этом же 7840HS) — тогда наружу не уходит ничего.

## Рабочая схема

Кодекс в Докере с одной примонтированной папкой «общее» → чувствительное в отдельном каталоге вне монтирования → если чувствительное надо обработать ИИ, это делает локальная модель, а не Кодекс.

## Правила для инструкции Кодексу (вписать в ТЗ)

Уточнение от 2026-06-16: как гонять скрипт-обработчик чувствительных данных, не сливая их Кодексу.

- **Путь — это просто текст.** Если в скрипте прописан путь к секретам, в Кодекс утекает строка с путём, а не содержимое файла. Сами данные попадут в контейнер только при монтировании папки или если кто-то прочитает файл и положит его текст внутрь.
- **Запуск скрипта ≠ отправка данных в модель.** Когда скрипт читает файл и считает — это вычисление на твоём железе, наружу не уходит ничего. На сервер модели идёт только то, что попало Кодексу в контекст: прочитанная им папка и сообщения чата.
- **Путь к секретам — аргументом при запуске, не зашивать в код.** Тогда даже строка пути в контекст Кодекса не попадёт. Скрипт пишется универсальным: обрабатывает любую папку, которую укажут.
- **Боевой прогон — вне контейнера Кодекса.** Реальные данные и контейнер Кодекса не должны встречаться в одном запуске. Отладка внутри Кодекса — на фейковых данных того же формата; настоящий прогон — снаружи, на своём железе или в чистом контейнере без сети.
- **Главная живая дыра — копипаст, а не монтирование.** Если при отладке копировать Кодексу ошибки и вывод, где светятся реальные данные («смотри, не работает, вот что выдало») — данные уедут к модели через чат. Отлаживать молча: показывать только текст самой ошибки, без строк с содержимым.
