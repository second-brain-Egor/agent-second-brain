# Nate Herk — правила проекта

## Цель

Собирать и поддерживать базу знаний по материалам YouTube-канала Nate Herk:
https://youtube.com/@nateherk

Материалы обрабатываются заранее и хранятся локально. Анализ и сведения из базы предоставляются Егору по его запросу.

## Периодическая обработка

- Проверять канал ежедневно в 07:00 по Москве и автоматически скачивать и обрабатывать только новые ролики, опубликованные после уже учтённых.
- Старые ролики из архива канала не скачивать по расписанию; обрабатывать их только по отдельной команде Егора.
- Не назначать периодичность, даты и напоминания самостоятельно.
- Не обрабатывать повторно уже сохранённые ролики без причины.
- Для каждого нового ролика автоматически собирать метаданные, описание, субтитры, транскрипцию, видео и отобранный визуальный ряд.
- После каждой проверки отправлять Егору в Telegram очень короткий итог: появились ли новые ролики, сколько их и были ли ошибки. Для каждого нового ролика указывать русское название и одним коротким абзацем простыми словами объяснять, о чём он. Не присылать тему, содержание и вывод отдельными блоками. Не использовать английские слова, кроме точных названий моделей и сервисов, которые нельзя перевести. Технические подробности без отдельного запроса не присылать. Весь утренний отчёт должен помещаться в одно сообщение и по возможности не превышать 1200 знаков.
- После каждой проверки канала обязательно автоматически запускать очередь аналитических карточек, даже если новых роликов нет: это позволяет продолжить материал, не завершённый в предыдущем запуске.
- Проверка канала считается успешной только после завершения очереди без ошибок. Если карточку создать не удалось, отправлять краткое сообщение об ошибке, а при следующем ежедневном запуске автоматически повторять только незавершённые карточки.

## Отчёт об обработке видео

Пользовательский отчёт в Telegram писать кратко, простым и понятным языком, без лишних технических деталей и перегруженных формулировок. Полная карточка остаётся подробной для базы знаний, но утреннее сообщение не должно её пересказывать.

Для каждого обработанного видео обязательно указывать:

- `## Тема` — о чём видео;
- `## Краткое содержание` — аннотация в 1–3 предложениях;
- `## Основной вывод` — главный вывод автора или явно отмеченное отсутствие вывода.

Эти три заголовка должны быть отдельными и точными: не объединять их в раздел
«Кратко» и не заменять разделом «Основные идеи». Раздел «Основные идеи и тезисы»
идёт после них и не заменяет обязательные поля отчёта.

Формулировка «видео обработано» без описания содержания недопустима.

## Автоматизация и экономия токенов

- Сбор и предварительную обработку выполнять программно, до работы агента.
- Использовать существующий общий инструмент:
  `vault/projects/Скрипт для выгрузки видео/scripts/выгрузка-видео.py`.
- Видео программно разбивать на кадры по смене сцен, удалять дубликаты и близкие кадры.
- По возможности автоматически исключать кадры с «говорящей головой», если они не несут самостоятельной информации.
- Сохранять уникальные и содержательные изображения: интерфейсы, схемы, таблицы, демонстрации действий, результаты и другие визуальные детали, важные для понимания ролика.
- Агент анализирует уже подготовленные транскрипцию и отфильтрованный визуальный ряд, не просматривая без необходимости весь исходный видеопоток.

## Карточка ролика

Для каждого ролика создавать отдельную папку в `videos/` и отдельную карточку анализа. Карточка должна содержать:

- название, дату публикации, ссылку и длительность;
- краткое содержание;
- основные идеи и тезисы;
- инструменты, сервисы, приёмы и последовательности действий;
- важные детали из визуального ряда со ссылками на соответствующие кадры;
- практическую ценность для Егора;
- ограничения, спорные места и то, что требует проверки;
- связи с другими роликами и уже накопленными знаниями.

Не добавлять выводы, которых нет в исходных материалах. Факты, мнение автора и вывод агента явно разделять.

## Обязательный порядок обработки

Новый материал считается полностью обработанным только после всех этапов:

1. Сохранены метаданные, описание, комментарии и исходная ссылка.
2. Скачано видео, получена транскрипция, извлечены и проверены содержательные кадры.
3. Создан `analysis.md` по структуре раздела «Карточка ролика».
4. В карточке проверены ссылки на кадры и отделены факты, мнение автора и вывод агента.
5. `summary.md` дополнен новыми знаниями и связями без дублирования старого материала.
6. Проверено наличие и непустое содержимое всех обязательных файлов.

Наличие `video.mp4`, транскрипции и кадров означает только подготовку исходников. Нельзя называть материал «обработанным», «готовым» или «завершённым», пока нет проверенной карточки `analysis.md` и обновления `summary.md`.

Если любой этап не выполнен, фиксировать конкретный незавершённый этап и продолжать с него при следующем запуске. Сбой одного этапа не должен скрываться общим статусом `complete`.

Долгую очередь карточек запускать через отдельный фоновый обработчик `scripts/nate-herk-process-pending.sh`. Обработчик обязан брать все папки без непустого `analysis.md`, работать последовательно под файловой блокировкой, вести журнал каждого этапа и продолжать очередь после завершения отдельного диалога. После сбоя повторный запуск должен пропускать готовые карточки и снова брать незавершённые.

Нельзя сообщать Егору, что очередь запущена или закончена, только по факту запуска команды. Перед ответом обязательно проверить живой процесс, журнал и наличие непустых `analysis.md`; завершением считать только фактически готовые карточки и обновлённую сводку.

Для любого другого присланного материала применять тот же принцип: сначала сохранить проверяемый источник, затем извлечь содержание и важные детали, создать структурированную карточку, связать её с существующими знаниями и только после проверки считать работу завершённой.

## Структура хранения

- `videos/` — материалы и карточки отдельных роликов.
- `analysis/` — сводные и тематические разборы по запросам Егора.
- `summary.md` — накопительная карта знаний по каналу.
- `download-state.json` — состояние выгрузки, чтобы не создавать дубликаты.
- `logs/` — журналы автоматических запусков и ошибок.

Исходные материалы сохранять так, чтобы любой вывод можно было проверить по транскрипции, метаданным или кадрам.

## Выдача информации

- По запросу Егора сначала использовать локальную базу проекта.
- Объединять сведения из нескольких роликов, когда это помогает ответить на вопрос.
- Отвечать кратко и предметно, сохраняя ссылки на исходные ролики и конкретные материалы.
- При появлении новых данных дополнять существующую базу, а не создавать разрозненные дубли.
