# Grok Bot получил два крупных обновления — что сделать сейчас

- Дата публикации: 9 октября 2026 года
- Источник: канал Нейта Херка
- Ссылка: https://www.youtube.com/watch?v=MgvwZaDPCs4
- Длительность: 9:11

## Тема

Два обновления Grok Bot и перенос Claude Code на его облачный компьютер.

## Краткое содержание

Нейт показывает автоматический выбор моделей и бесплатный встроенный поиск по X. Затем он переносит Claude Code на компьютер Grok Bot и объясняет, зачем дробить большие навыки.

## Основной вывод

После обновления стоит заменить платный поиск по X, разделить большие навыки и при необходимости запускать Claude Code через компьютер Grok Bot.

## Основные идеи и тезисы

### Что показано и сказано в ролике

- Первое обновление — автоматический выбор модели под запрос. В показанной публикации Илона Маска названы Claude Opus 5.5, Midjourney, Suno и другие внешние программные службы; для простых запросов обещаны небольшие быстрые модели, а для сложных — крупные: [публикация о выборе моделей](frames/frame-00001.jpg).
- Нейт предполагает, что Claude Opus 5.5 будет выполнять сложные задачи, а будущая быстрая версия Grok 4.8 — большинство простых. Интерфейс Grok Bot при этом не показывает выбранную модель, уровень усилий или причину выбора, поэтому в ролике нельзя подтвердить, какая модель выполнила конкретный запрос.
- Автор ожидает, что автоматический выбор продлит недельный лимит и даст удачное сочетание скорости и качества. Это ожидание, а не измеренный результат: сравнения одинаковых задач до и после обновления в ролике нет.
- Часть пользователей, чьи ответы показаны под публикацией, не хочет передавать запросы моделям Anthropic и просит возможность отказаться. Нейт считает общее направление полезным, но тоже хочет видеть и выбирать модель для отдельного навыка.
- Второе обновление — встроенная возможность Grok Bot искать, читать и отслеживать публикации в X: [объявление Grok Bot](frames/frame-00002.jpg). Раньше Нейт использовал платный программный доступ X и, по его словам, тратил примерно пять долларов в неделю.
- Нейт просит агента X перевести его часовую проверку на встроенный поиск, а затем сообщить об изменении другим агентам, которые собирают сведения из X. В беседе агент утверждает, что получил десять свежих публикаций без расхода платных единиц: [перевод одной проверки на встроенный поиск](frames/frame-00003.jpg).
- Для проверки автор просит агента Miner найти мнения о Claude Motion. Агент возвращает пять публикаций и сообщает нулевую цену, расход пяти чтений из бесплатного дневного запаса в тысячу и предел в тридцать чтений в минуту: [ответ Miner и заявленные пределы](frames/frame-00007.jpg). Сам Нейт предупреждает, что Grok Bot может неточно описывать собственные правила, поэтому эти числа нельзя считать подтверждёнными условиями службы.
- Автоматический выбор моделей меняет устройство навыков. По мысли автора, один большой навык из семи разнородных шагов может целиком попасть одной модели, тогда как отдельные запросы позволят простые части отдать быстрой модели, а рассуждение, оформление и оценку качества — более сильной.
- Предположение о выборе одной модели на весь запрос Нейт выводит из возможной сложности передачи контекста и кэша между моделями. В ролике нет документации или наблюдаемого журнала, который подтверждал бы это устройство.
- Передача запроса от одного агента нескольким другим создаёт несколько отдельных точек выбора модели. Поэтому число агентов и число обращений влияют на расход и качество не меньше, чем модель первого агента.
- Дополнительный приём — установить Claude Code или Codex через командную строку на постоянно работающий облачный компьютер агента Grok Bot, войти в собственную учётную запись и открыть нужное хранилище кода. Так Grok Bot становится мобильной точкой доступа к другому средству разработки, а не заменяет его моделью Grok.
- В показанном примере агент Klaus клонировал хранилище `Herk-2.0` вместе с `CLAUDE.md` и навыками, открыл Claude Code и запустил Claude Opus 5.5 по плану Claude Team: [Claude Code в терминале](frames/frame-00010.jpg), [подтверждение среды в Grok Bot](frames/frame-00011.jpg).
- На экране Claude Code включён режим автоматического одобрения изменений и команд. Это удобно для долгой работы, но существенно расширяет права вложенного агента на облачном компьютере.
- Нейт предпочитает хранить подключения через ключи программных служб, чтобы переносить рабочие файлы в другую среду. Однако в ролике не показаны безопасная передача секретов, их разграничение между агентами и отзыв после завершения работы.

### Позиция автора

- Автоматический выбор моделей — шаг в правильную сторону, если он действительно сочетает скорость, качество и экономию лимита.
- Пользователю всё же нужны видимость выбранной модели, показ уровня усилий, ручной выбор для навыка и возможность отказаться от нежелательного поставщика.
- Большие навыки следует делить на меньшие части в соответствии со сложностью работы, а не держать весь процесс в одном запросе.
- Платный доступ X имеет смысл заменить встроенным поиском Grok Bot там, где тот уже покрывает задачу.
- Claude Code внутри постоянно включённого Grok Bot даёт автору удобный доступ к своим проектам с телефона; из похожих облачных средств он предпочитает Grok Bot сервисам Dots и Muse.

### Вывод из разбора

- Скрытый выбор модели нельзя считать управлением качеством. Пока Grok Bot не показывает маршрут, в журнале следует хранить значение «модель неизвестна» и оценивать наблюдаемые признаки: вход, результат, время, расход, ошибки и подтверждённый внешний эффект.
- Дробление навыка полезно только по естественным границам данных и проверки. Слишком мелкие запросы добавляют передачи контекста, повторную работу и новые места сбоя; слишком крупный запрос не даёт отделить дешёвые шаги от требующих сильной модели.
- Сообщение одного агента другим об обновлении ещё не доказывает, что все их расписания и инструкции изменены. После массовой замены нужен перечень затронутых процессов и проверка каждого сохранённого источника данных.
- Бесплатный встроенный поиск следует оценивать не только по цене. Для рабочей замены платного доступа нужно сравнить полноту, свежесть, повторяемость, ссылки на исходные публикации, пределы чтения и поведение при исчерпании запаса.
- Claude Code внутри Grok Bot образует вложенный контур: Grok Bot даёт компьютер и удалённое управление, а Claude Code использует другую подписку, модель и собственные разрешения. Ошибку или расход нужно относить к правильному слою, а не к системе целиком.
- Общий файловый раздел компьютеров Grok Bot, клонированное хранилище, ключи и автоматическое одобрение команд создают широкую область возможного ущерба. Для такого запуска нужна отдельная ограниченная среда, а не полная копия личного рабочего компьютера.

## Инструменты, сервисы и материалы

- **Grok Bot** — предоставляет агентов, облачные компьютеры, автоматический выбор моделей и встроенную работу с X.
- **X** — источник публикаций и среда, которую Grok Bot теперь, по объявлению в ролике, умеет искать, читать и отслеживать без отдельного платного подключения.
- **Claude Opus 5.5** — названа среди моделей автоматического выбора и показана внутри Claude Code на компьютере агента Klaus.
- **Grok 4.8** — будущая на дату ролика быстрая модель, которой, по словам Илона Маска в пересказе автора, планируют поручать простые запросы.
- **Midjourney** и **Suno** — названы в публикации как внешние службы для изображений и музыки; их вызов в самом ролике не показан.
- **Claude Code** — установлен на облачный компьютер Grok Bot и запущен по отдельному плану Claude Team.
- **Codex** — назван как ещё одно средство, которое можно установить тем же способом; отдельная установка в ролике не показана.
- **Cursor**, **SpaceX** и **SuperGrok** — упомянуты как варианты получения доступа к Grok Bot, но условия планов автор называет запутанными и не разбирает.
- **Dots** и **Muse** — названы как похожие службы с облачными компьютерами; прямого сравнения на одинаковой задаче нет.

## Приёмы и последовательность действий

### Замена платного поиска по X

1. Составить список агентов, навыков и расписаний, которые используют платный доступ X, и зафиксировать их текущую стоимость и ожидаемый результат.
2. Перевести на встроенный поиск одну обратимую проверку с низким риском, не меняя остальные условия.
3. На одинаковом наборе запросов сравнить число найденных публикаций, свежесть, ссылки, повторы, язык, порядок выдачи и время ответа.
4. Отдельно проверить заявленные дневной и минутный пределы, не принимая ответ самого агента за справочную документацию.
5. После удачной проверки менять процессы по одному. Для каждого подтвердить не сообщение «обновлено», а сохранённую инструкцию и результат следующего запуска.
6. Оставить понятное поведение при недоступности встроенного поиска или исчерпании запаса: остановка с сообщением, а не незаметно неполный отчёт.

### Разделение навыка под выбор моделей

1. Разложить процесс на шаги с явными входом, результатом и способом проверки.
2. Отделить простое извлечение, приведение формата и пересылку от рассуждения, проектирования и оценки качества.
3. Передавать между шагами только нужные данные и устойчивые ссылки на источники, чтобы не пересказывать весь контекст заново.
4. Запускать каждый шаг отдельным запросом только там, где это даёт наблюдаемую экономию или качество.
5. Сохранять для каждого обращения время, расход, результат проверки и выбранную модель, если Grok Bot когда-либо начнёт её показывать; до этого не угадывать маршрут.
6. Сравнить разделённую и цельную версии на нескольких одинаковых задачах до массового перехода.

### Запуск Claude Code внутри Grok Bot

1. Создать отдельного агента и отдельное ограниченное хранилище или рабочую ветвь без производственных секретов.
2. Установить Claude Code из доверенного источника через командную строку облачного компьютера.
3. Лично пройти вход и проверить, какая учётная запись, подписка и модель выбраны.
4. Клонировать только нужное хранилище и передать `CLAUDE.md`, `AGENTS.md` и навыки через систему контроля версий.
5. Передавать ключи отдельно, с минимальными правами и сроком действия; не хранить их в хранилище кода или общей памяти агентов.
6. Отключить автоматическое одобрение команд для первого запуска и отдельно разрешать внешние, удаляющие и меняющие права действия.
7. Проверить чтение проекта, одну небольшую обратимую правку, журнал команд и видимость результата с телефона.
8. После работы проверить изменения, удалить лишние данные доступа и убедиться, что отзыв учётной записи или ключа действительно прекращает доступ.

## Важные детали визуального ряда

- В публикации Илона Маска прямо перечислены Claude Opus 5.5, Midjourney, Suno и другие внешние службы, но нет схемы выбора, данных о цене или правила отказа: [исходное объявление](frames/frame-00001.jpg).
- Отдельная публикация Grok Bot обещает поиск, чтение и отслеживание X. Кадр подтверждает объявление функции, а не качество её работы: [объявление о работе с X](frames/frame-00002.jpg).
- Агент X сообщает, что встроенный поиск отделён от платного подключения, нашёл десять публикаций и обновил часовую проверку: [беседа об изменении источника](frames/frame-00003.jpg).
- Miner показывает пять найденных публикаций о Claude Motion и заявляет нулевую цену. На том же экране указаны остаток 995 из 1000 и предел 30 чтений в минуту; эти числа пришли от агента, а не из настроек тарифа: [результат испытания](frames/frame-00007.jpg).
- На компьютере Klaus открыт Claude Code 2.1.295 с Claude Opus 5.5 и планом Claude Team. Экран также предупреждает, что режим автоматического одобрения может выполнять правки и команды без отдельного вопроса: [среда Claude Code](frames/frame-00010.jpg).
- В чате Grok Bot видны путь `~/repos/Herk-2.0`, наличие `CLAUDE.md` и навыков, выбранная Claude Opus 5.5 и включённое автоматическое одобрение: [подтверждение настройки агентом Klaus](frames/frame-00011.jpg).

Все шесть ссылок проверены: файлы существуют и соответствуют описанным фрагментам. Кадры 4 и 5 относятся к рекламной вставке о бесплатном шаблоне, кадры 6 и 12 показывают автора, а кадры 8 и 9 повторяют компьютер Miner и сведения об ограничениях без новой самостоятельной детали.

## Практическая ценность для Егора

- Для базы Егора скрытый выбор моделей полезно воспринимать как недоверенный внутренний механизм. Процесс должен быть проверяемым по результатам даже тогда, когда точная модель и уровень усилий неизвестны.
- Разделение больших навыков может снизить расход сильной модели, но его стоит делать по границам ответственности: сбор источников, извлечение фактов, вывод, оформление и окончательная проверка. У каждого шага должен быть свой проверяемый результат.
- Встроенный поиск Grok Bot по X подходит для недорогого наблюдения и поиска идей, если он сохраняет ссылки на исходные публикации. Для критического исследования нужен контрольный источник или платный доступ с понятными условиями полноты.
- Массовое сообщение агентам удобно для оповещения, но изменения конфигурации лучше делать через проверяемые файлы и перечень процессов. Иначе часть расписаний может продолжить работать по старому источнику.
- Claude Code внутри Grok Bot даёт постоянно доступную среду и управление с телефона. Для Егора это может быть запасной удалённый путь к ограниченному проекту, но не место для всех личных файлов, ключей и производственных доступов.
- Вложенный запуск нужно наблюдать по слоям: запрос в Grok Bot, действие на его компьютере, работа Claude Code, изменения в хранилище и внешний результат. Сообщение любого одного слоя о завершении не подтверждает остальные.
- Включённое на кадре автоматическое одобрение особенно опасно в общей файловой среде. Безопасный первый вариант — отдельное хранилище, короткоживущие ключи, ручное подтверждение опасных команд и проверка различий перед отправкой изменений.

## Ограничения, спорные места и что требует проверки

- Ролик опирается на публикации и одну короткую демонстрацию, а не на документацию Grok Bot или независимое измерение автоматического выбора моделей.
- Ни в одном показанном запросе не видны фактически выбранная модель, уровень усилий, цена или причина маршрута. Утверждения о Claude Opus 5.5 и будущей Grok 4.8 нельзя привязать к конкретным ответам Miner и X.
- Предположение о выборе одной модели на весь запрос — рассуждение автора. Grok Bot может делить работу иначе, а устройство службы может измениться.
- Не проверено, продлевает ли новый выбор недельный лимит. Нет одинакового набора задач, исходных значений расхода и повторных запусков.
- Не разобраны передача данных внешним поставщикам, хранение запросов, место обработки и возможность отказаться от отдельной модели. Это важно до работы с частными сведениями.
- Указанные Miner бесплатный запас в тысячу чтений, предел тридцать в минуту и время обновления исходят из ответа самого агента. Автор прямо предлагает относиться к ним осторожно.
- Пять найденных публикаций не доказывают полноту поиска X. Нет эталонного набора, сравнения с платным доступом, проверки удалённых и закрытых публикаций или повторяемости выдачи.
- Экономия примерно пяти долларов в неделю — личная оценка автора. Не показаны счета, точное число запросов и цена пропущенных данных.
- Сообщение агента X другим агентам не подтверждает, что их инструкции и расписания действительно изменились; показана только одна беседа.
- Вход в Claude Code внутри чужой облачной среды расширяет доверенную область до Grok Bot и общей файловой системы его агентов. В ролике не проверены изоляция, двухфакторный вход, отзыв сеанса, резервное восстановление и доступ сотрудников службы.
- Режим автоматического одобрения разрешает правки и команды без отдельного вопроса. Не показаны ограничения на удаление, отправку изменений, сетевой доступ и чтение секретов.
- Установка Codex тем же способом только заявлена. На кадрах подтверждён запуск Claude Code, но не Codex.
- Сравнение с Dots и Muse основано на предпочтении автора, а не на одинаковых испытаниях цены, качества, безопасности и устойчивости.

## Разделение фактов, мнения автора и вывода агента

- **Факты исходного материала:** показаны публикации об автоматическом выборе моделей и встроенной работе с X; агент Miner вернул пять публикаций и заявил нулевую цену; на компьютере Klaus открыт Claude Code с Claude Opus 5.5, планом Claude Team, клонированным хранилищем и автоматическим одобрением команд.
- **Мнение автора:** обновления движутся в правильную сторону; крупные навыки нужно дробить; встроенный поиск стоит использовать вместо платного доступа X; Grok Bot удобнее Dots и Muse для его ежедневной работы.
- **Вывод агента:** скрытый маршрут нельзя принимать за проверяемую оптимизацию, слова агента о собственных пределах нельзя считать документацией, а вложенный Claude Code требует отдельной границы прав, секретов и подтверждения результата.
