# Карточка ролика: девять приёмов работы с Grok Bot

Дата: 2026-08-19  
Длительность: 10:24  
Ссылка: https://www.youtube.com/watch?v=TMPUUyQC5aM

## Кратко

Автор собирает практики организации команды облачных агентов Grok Bot: подробное интервью, единая точка входа, специалисты, разделение памяти, внешние подключения, журнал работ, обучение показом, расписания и сохранённые браузерные профили.

## Девять приёмов

1. Навык Grill Me подробно расспрашивает владельца о бизнесе, целях и процессе и сохраняет контекст.
2. Главный агент — «руководитель аппарата»: пользователь общается только с ним, а он передаёт работу специалистам и возвращает результат.
3. Состав команды подбирает сам главный агент на основе целей и уже существующих ролей; дублирующих помощников создавать не нужно.
4. Контекст явно делится на общий для всех агентов и личный для конкретного агента; отдельные темы можно вести в ветках.
5. Composio расширяет набор подключений к YouTube, Reddit, LinkedIn, Perplexity и другим системам.
6. Отдельный навык записывает задачи агентов в ClickUp: статус, исполнитель, заметки, ссылки и ход выполнения.
7. Визуальную процедуру можно показать через запись экрана; система превращает демонстрацию в повторяемый навык.
8. Рутины запускают навыки и агентов по расписанию либо событию в облаке без включённого компьютера.
9. В агентном компьютере сохраняются авторизованные профили сайтов, поэтому пароль не требуется передавать в чат.

## Практическая ценность для Егора

Для Agent Second Brain наиболее полезны четыре идеи: одна точка общения, специализированные исполнители без дублирования, явное разделение общей и локальной памяти и единый журнал фоновой работы. Обучение через демонстрацию может пригодиться для сайтов, где нет API.

## Применимость к Codex и Claude Code

Схема не привязана к Grok Bot. В Codex её можно собрать через главный поток, специализированных субагентов и проектные инструкции; в Claude Code — через главный сеанс, пользовательских или проектных subagents, а для самостоятельного обмена между исполнителями — agent teams. Переносятся роли, правила маршрутизации, общая база знаний и журнал работы. Специфичны для Grok Bot только его интерфейс, встроенные рутины и способ хранения браузерных профилей.

Практический предел: обычные субагенты чаще возвращают результат координатору, но не образуют полностью автономную организацию сами по себе. Для надёжной команды всё равно нужны явные владельцы задач, ограничения инструментов, единый журнал и контроль повторных действий.

## Ограничения и проверка

- Это личный опыт автора за короткий период, а не систематический тест надёжности Grok Bot.
- Название Composio в автоматической транскрипции и конкретный набор подключений следует сверять с текущей документацией.
- Сохранённый браузерный профиль удобнее передачи пароля в чат, но остаётся чувствительной точкой доступа; нужны минимальные разрешения и отдельные учётные записи.
- Расписания и внешние действия требуют журнала, идемпотентности и ограничений, чтобы агент не повторял операции.
