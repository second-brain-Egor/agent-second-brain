# Карточка ролика: браузерный агент Codex для автоматизации интерфейсов

Дата: 2026-08-13  
Длительность: 16:27  
Ссылка: https://www.youtube.com/watch?v=CB5bG4mvnS0

## Кратко

Нэйт показывает browser use и computer use в Codex на четырёх примерах: тестирование веб-формы, скачивание банковских выписок, исследование ленты X и подготовка черновика X Article, а также изменение настройки настольного приложения. Главный практический тезис ролика не в том, что браузерный агент должен заменить обычную автоматизацию: сначала следует искать API, затем детерминированный скрипт или макрос и лишь при необходимости визуального распознавания и рассуждения использовать browser/computer use.

## Основные идеи и результаты

- Встроенный браузер Codex позволяет человеку и агенту работать с одной страницей: пользователь может выбрать и аннотировать конкретные элементы интерфейса, а агент — нажимать, вводить данные, менять размер окна и проверять сценарии.
- В демонстрации тестирования формы агент проверил основной путь, обязательность полей, возврат к предыдущим шагам, перезапуск, консольные ошибки, мобильную адаптацию и клавиатурное управление. Он сообщил о семи проблемах, включая пропуск некорректных контактных данных, сброс кода страны, ошибки адаптивности и доступности с клавиатуры.
- Browser use может работать в видимом режиме, когда действия агента наблюдаемы, или headless в фоне. Автор предлагает задавать длительную проверку через цель с количественным критерием, например пройти 100 уникальных edge cases.
- Для Relay автор один раз описал путь естественным языком: открыть Accounts, найти Statements, выбрать два счёта, скачать CSV и сохранить их в нужную папку. После успешного прогона последовательность была сохранена как skill, пригодный для повторного или запланированного запуска.
- Автор показывает сохранённые браузерные сессии и встроенный менеджер паролей. При истечении банковской сессии учётные данные импортировались из CSV и использовались для повторного входа; двухфакторное подтверждение при необходимости остаётся ручным.
- В X агент использовал уже авторизованную сессию, просмотрел ленту, а в другом процессе превратил YouTube-видео в черновик статьи: подготовил текст и обложку, извлёк кадры из видео, загрузил и расставил изображения. Публикацию оставили человеку после проверки.
- Computer use отличается областью действия: browser use работает со страницами, а computer use — с локальными приложениями и настройками. В примере агент открыл Glaido и включил опцию Bluetooth-устройств; сначала он ошибочно счёл действие чувствительным системным разрешением, затем распознал его как настройку приложения.
- По оценке автора, отдельная автоматизация статьи экономит лишь 5–10 минут, но ценность растёт при накоплении переиспользуемых навыков, параллельной работе без переключения контекста и объединении шагов в цепочки.

## Как выбирать способ автоматизации

1. Сначала использовать API: по мнению автора, это обычно быстрее, дешевле и стабильнее и покрывает подавляющее большинство задач.
2. Если API нет или он не подходит, проверить возможность детерминированного скрипта или макроса: фиксированную последовательность кликов не нужно оплачивать как рассуждение визуального агента.
3. Browser use применять, когда расположение и состояние интерфейса меняются и следующий шаг требует распознавания экрана или выбора по контексту.
4. Computer use применять только для действий в локальных приложениях, сохраняя ограничения на чувствительные системные разрешения.
5. Перед расписанием многократно прогнать навык под наблюдением, сузить допустимые действия и оставить ручное подтверждение для опасных или необратимых операций.

## Инструменты, сервисы и приёмы

- Codex desktop app со встроенным браузером, аннотациями элементов, browser use, scheduled routines и переиспользуемыми skills.
- Headed-режим для наблюдаемой отладки и headless-режим для длительных фоновых проверок.
- Browser QA с негативными данными, альтернативной навигацией, мобильным viewport, клавиатурой и попытками нарушить основной сценарий.
- Relay как пример сайта без подходящего API для конкретной операции; загрузка выписок и раскладка файлов по проекту.
- Импорт паролей в браузерный менеджер из CSV с полями `name`, `url`, `username`, `password`, `notes`; секреты не вводятся в чат.
- X и YouTube как многошаговый контентный процесс: извлечение материала, создание статьи и изображений, заполнение авторизованного веб-интерфейса, сохранение в черновик.
- Отдельно устанавливаемый плагин computer use для управления настольными приложениями.

## Практическая ценность для Егора

Для Agent Second Brain полезна трёхступенчатая архитектура автоматизации: API для устойчивого обмена данными, детерминированный скрипт для стабильного интерфейсного пути и визуальный агент как запасной слой для динамического UI. Это снижает стоимость и вариативность, не отказываясь от задач, для которых интеграции нет.

Browser use особенно ценен как независимый приёмочный тест интерфейсов: агенту можно дать не реализацию, а пользовательскую цель и перечень атакующих сценариев, затем сохранить отчёт с pass/fail и только после него поручить исправления. Для операций с авторизованными аккаунтами нужны изолированные учётные данные, минимальные права, наблюдаемые тестовые прогоны, ручное подтверждение публикаций и финансовых действий и явный запрет на обход 2FA.

## Ограничения, спорные места и что требует проверки

- Ролик демонстрирует отдельные успешные прогоны, но не измеряет повторяемость, процент ошибок, стоимость, длительность или качество на серии одинаковых запусков.
- Утверждения «может буквально всё» и «API покрывает 95%» — риторика и оценка автора, а не проверенные показатели.
- Работа с Relay показана на реальном финансовом интерфейсе. Автор рекомендует десять наблюдаемых прогонов и строгий сценарий, однако визуальный агент всё равно может ошибиться после изменения UI; показанная проверка недостаточна для безопасной автономной работы с деньгами.
- Импорт паролей из незашифрованного CSV сам создаёт риск утечки. В ролике не разобраны хранение и удаление файла, шифрование, доступ к профилю браузера, журналирование и восстановление после компрометации.
- Сохранённая сессия не гарантируется: банковские сервисы завершают её, а 2FA, CAPTCHA, антибот-защита и чувствительные разрешения могут остановить процесс.
- Созданная X-статья и обложка оценены лишь визуально самим автором; он прямо отмечает, что генерация thumbnail ещё не доработана. Качество текста и фактическая точность отдельно не проверялись.
- Рассказ относится к показанной версии Codex. Наличие функций, названия меню, ограничения и тарифные условия могут измениться и требуют проверки перед внедрением.

## Разделение фактов, мнения автора и вывода агента

- **Факты исходного материала:** в показанном запуске агент нашёл семь проблем формы; сохранил выписки Relay в папку проекта; использовал импортированную запись менеджера паролей; открыл авторизованный X и подготовил черновик статьи; computer use изменил настройку Glaido.
- **Мнение автора:** browser use Codex — лучший из опробованных им вариантов; API обычно является первым выбором, макрос — вторым, а визуальный агент нужен только при необходимости распознавания и рассуждения; основная отдача приходит от накопления и связывания навыков.
- **Вывод агента:** browser/computer use следует считать контролируемым адаптером последней мили, а не основой критичного процесса. Надёжный контур требует минимальных полномочий, тестовой среды, структурированного отчёта, ограничений действий, повторных прогонов и ручного шлюза перед необратимым шагом.

## Связи с базой

- Дополняет сравнение Codex и Claude Code: большое число автоматических тестов само по себе не обеспечивает качество, но браузерный агент полезен для независимой проверки реального пользовательского пути и ошибок, которые не покрыты unit-тестами.
- Согласуется с принципом измеримого внедрения: экономию времени нужно проверять на повторяющемся процессе, а не выводить из эффектной единичной демонстрации.
- Развивает тему skills и агентных оболочек: повторяемая ценность возникает, когда естественно-языковой эксперимент превращён в ограниченный, проверенный и наблюдаемый навык, а способ исполнения выбран по стабильности и цене.
