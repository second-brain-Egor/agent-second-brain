## @FamilyManMoving

Use Git worktrees   - tell each agent to use its own work tree. What happens is it creates a mini branch within your repository, that each agent works from independent of all other work in the repository. At the end, you can go ahead and merge together using an orchestra agent. Of course, the even easier answer is to simply clone your repository for each of the models that you wish to test, and make sure each is working independent of the other. 

I do this frequently. I actually deploy agent swarms for Business and the last thing you ever want to see happen is for two business workflows to start stepping on each other with multiple agent analytics.

Cloning separate repos is the easy answer for small projects like this, but with Enterprise scale you need to make sure work trees or something similar are used for every agent. Build a harness around it don’t let the agent have a choice.
