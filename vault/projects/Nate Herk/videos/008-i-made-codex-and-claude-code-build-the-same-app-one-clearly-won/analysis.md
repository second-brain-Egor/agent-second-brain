# Карточка ролика: Codex и Claude Code строят одно приложение

Дата: 2026-08-14  
Длительность: 21:14  
Ссылка: https://www.youtube.com/watch?v=WCrnS09vpfo

## Кратко

Нэйт дал Codex и Claude Code одинаковую высокоуровневую задачу: силами оркестратора и субагентов исследовать, построить и проверить готовую к эксплуатации альтернативу Typeform. В этом единственном опыте Claude Code быстрее и дешевле создал более понятный и функциональный продукт, тогда как Codex построил более сложную архитектуру и провёл гораздо больше тестов, но хуже ограничил объём и не превратил техническую глубину в лучший пользовательский опыт.

## Основные идеи и результаты

- Запрос задавал три фазы — исследование, разработку и проверку — и запрещал останавливаться на прототипе или первом успешном билде. После опыта автор решил, что между исследованием и разработкой стоило явно добавить фазу продуктового планирования.
- Claude Code создал Formora: визуально более слабый, но понятный конструктор с рабочей публикацией формы, записью ответа, результатами и рабочими пространствами.
- Codex создал Realform: более привлекательный внешне и насыщенный возможностями продукт, но его редактор оказался перегруженным; часть элементов, тем и публикационных функций выглядела демонстрационной или не работала ожидаемым образом.
- Ошибки сохранились в обоих приложениях. В Realform автор обнаружил неработающее превью изображения, неудобное подтверждение и элементы темы без видимого эффекта. В Formora — недоступный пункт выхода, неверную нумерацию вопросов, несинхронное выделение, неудобную обратную навигацию и сохранение названия только после повторной публикации.
- По приведённым автором данным Claude Code использовал около 2 млн выходных токенов, 35 субагентов и примерно 2 800 вызовов инструментов за 5 ч 32 мин. Codex — около 11 млн токенов, 126 субагентов и 32,5 тыс. вызовов за 61–62 часа.
- Claude Code выполнил 296 unit-тестов, 199 test cases и 102 браузерных теста; Codex — 2 300, 341 и 391 соответственно. Больший объём тестов не предотвратил заметные продуктовые и интерфейсные проблемы.
- В анонимизированной сравнительной оценке Claude Code выиграл по продуктовому суждению, управлению объёмом и эффективности; Codex — по архитектуре, исполнению, тестированию и надёжности. Общим победителем был выбран Claude Code.
- Автор не считает результат универсальным рейтингом инструментов: он связывает различия с формой задания, моделями, оболочками и характером конкретного проекта и рекомендует регулярно повторять собственные прикладные сравнения.

## Как был устроен эксперимент

1. Обоим инструментам передали один и тот же `/goal`: создать оригинально брендированную production-ready альтернативу Typeform.
2. Агентам поручили самостоятельно оркестрировать исследование продукта, разработку и многократную проверку приложения.
3. Автор не смотрел результаты до демонстрации, затем вручную прошёл ключевые пользовательские сценарии: регистрацию, создание и настройку формы, ветвление, дизайн, публикацию и просмотр ответов.
4. После раскрытия инструментов он сопоставил журналы сессий: стоимость, токены, длительность, число субагентов, вызовов инструментов и тестов.
5. Консолидированные и обезличенные журналы были переданы Codex для сравнительной оценки по продукту, архитектуре, надёжности и эффективности.

## Инструменты, сервисы и приёмы

- Claude Code и Codex с многоагентной оркестрацией через `/goal`.
- Один и тот же целевой запрос и одинаковые категории оценки для сравнительного прогона.
- Ручной сквозной тест реальным пользователем поверх автоматически созданных тестов.
- Анализ журналов сессий и количественных показателей работы агентов.
- Анонимизация результатов перед итоговым сравнением, чтобы не раскрывать оценщику название инструмента.
- Предлагаемая автором специализация: Claude Code — для планирования, креативного исследования и определения пути; Codex — для конкретно заданной реализации, adversarial review, поиска ошибок, крайних случаев и усиления надёжности.

## Практическая ценность для Егора

Для Agent Second Brain главный урок — заранее разделять продуктовую достаточность и инженерную полноту. Число агентов, тестов и инструментальных вызовов не является метрикой полезного результата: перед запуском стоит определить ключевой пользовательский путь, обязательные функции, критерии остановки, бюджет и то, что сознательно откладывается.

Полезен двухконтурный процесс: сначала планирование и ограничение scope вокруг реального пользовательского сценария, затем независимая проверка архитектуры, безопасности, отказов и крайних случаев. При этом автоматические тесты нужно дополнять ручным сквозным тестом: оба обширно протестированных результата сохранили ошибки, которые обнаружились за несколько минут обычного использования.

## Ограничения, спорные места и что требует проверки

- Это один прогон одного задания без повторов, контролируемой среды и заранее опубликованной рубрики; он не доказывает общего превосходства Claude Code или Codex.
- Запуски не были полностью симметричны: использовались разные компьютеры и разные наборы моделей. По словам автора, в Codex работала GPT-5.6 Soul, а в Claude Code — несколько моделей, причём ожидаемый главный оркестратор сменился. Эти сведения взяты из ролика и независимо не проверялись.
- Стоимость Claude Code внутри ролика противоречива: сначала указано $832, позже в таблице оценки — примерно $447. Автор сам считает второе число вероятной ошибкой и говорит, что `/usage` и суммы по субагентам давали значение около $800. Поэтому точные коэффициенты «6,6 раза дешевле» нельзя считать надёжными.
- Заявление о production-ready не подтверждено развёртыванием, нагрузочным испытанием, аудитом безопасности или эксплуатацией реальными пользователями. В интерфейсах сразу нашлись дефекты, а Realform работал в demo workspace без реальной аутентификации.
- Число тестов не раскрывает их качество, покрытие и независимость. Сравнение количества unit, test cases и browser tests само по себе не измеряет пользовательскую ценность или надёжность.
- Итоговым оценщиком был Codex на подготовленной автором выжимке журналов. Анонимизация уменьшает один источник предвзятости, но не устраняет влияние отбора данных и критериев автора.
- Названия моделей, цены и поведение оболочек быстро меняются; переносить численные результаты на другой момент или тариф без нового теста нельзя.

## Разделение фактов, мнения автора и вывода агента

- **Факты исходного материала:** обоим инструментам дали один и тот же текст цели; в продемонстрированных приложениях автор прошёл одинаковые базовые сценарии; журналы, по его данным, показали сильную разницу во времени, числе агентов, вызовов и тестов; в обоих результатах вручную найдены ошибки.
- **Мнение автора:** Claude Code лучше понял продукт и высокоуровневую цель, а Codex полезнее для точного исполнения, тестирования, security review и поиска крайних случаев; в этом опыте затраты Codex были неоправданны.
- **Вывод агента:** эксперимент показывает не победителя вообще, а цену неограниченного scope. Для автономной разработки нужны отдельная фаза планирования, лимиты ресурсов, явные must/defer-решения и пользовательские acceptance-сценарии; глубокую проверку разумно запускать после фиксации продуктового ядра.

## Связи с базой

- Дополняет карточку о DeepSeek Harness и Claude Code: качество зависит не только от модели, но и от агентной оболочки, оркестрации и режима работы; сравнивать нужно на собственных задачах по качеству, стоимости и стабильности.
- Согласуется с накопленным принципом измеримого внедрения: вместо оценки по объёму работы следует заранее выбрать метрики результата и подтвердить их реальным использованием.
- Развивает идею разделения ролей в многоагентном процессе: генерация продуктового решения и независимая adversarial-проверка требуют разных критериев и могут выполняться разными инструментами.
