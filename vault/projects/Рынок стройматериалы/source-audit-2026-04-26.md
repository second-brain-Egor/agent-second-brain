# Проверка исходников прайса - 2026-04-26

## Что проверено

Проверены локальные вложения, дневная запись за 2026-04-26, сессионный журнал и лог Telegram-бота.

В сессионном журнале видны две отправки альбомом по три фото:

- 20:10:46 / 20:10:55 / 20:11:05 - три сообщения с фото, все записаны как `attachments/2026-04-26/img-201007.jpg`
- 20:34:26 / 20:34:26 / 20:34:37 - три сообщения с фото, все записаны как `attachments/2026-04-26/img-203355.jpg`

Фактически в папке вложений остались два файла:

- `vault/attachments/2026-04-26/img-201007.jpg`
- `vault/attachments/2026-04-26/img-203355.jpg`

Оба файла имеют одинаковый `sha256`: `d26ccd882d8e308a7aad0d9c94bc658c15bc64adc5ce4dc5b74310817a23c921`.

То есть в локальной папке остался один и тот же снимок страницы 2, сохраненный дважды.

## Причина

Фото из одного Telegram-альбома имеют одинаковую `message.date` до секунды. Старый код сохранения вложений называл файл только по времени `img-HHMMSS.jpg`.

Из-за этого три фото из альбома сохранялись в один и тот же путь и перезаписывали друг друга. В результате страницы 1 и 3 были потеряны локально, а последним сохраненным файлом осталась страница 2.

## Результат

В локальной базе проекта сначала была доступна только страница 2 из 3, хотя по журналу действительно приходили три фото.

После повторной отправки страницы 1 она обработана отдельно. После повторной отправки страницы 3 она также обработана отдельно.

Сейчас заведены карточки позиций 1-101:

- карточек: 101
- диапазон: 1-101

## Полнота

## Исправление на будущее

2026-04-26 исправлен механизм сохранения вложений: если файл с таким временем уже существует, новый снимок сохраняется с суффиксом `-2`, `-3` и так далее. Следующий альбом из нескольких фото не должен перетирать предыдущие страницы.
