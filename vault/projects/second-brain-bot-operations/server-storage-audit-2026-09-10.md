**План оптимизации с оценкой эффекта**

| Действие | Возможная экономия | Условия |
| --- | --- | --- |
| Очистить только Cache и Code Cache профиля «Форумхауса» | Около 1,00 ГБ | Перед выполнением убедиться, что профиль не занят браузером. Cookies, настройки профиля и реестр выгрузок сохранить. |
| Очистить кэш пакетов uv у Егора, npm у root и /var/cache/apt | Около 0,50 ГБ | Использовать штатную очистку соответствующего кэша, не удалять установленные библиотеки. Для uv учтены жёсткие ссылки: удаление разделяемых файлов не даёт полной экономии. |
| Убрать подтверждённые дубликаты вложений «Форумхауса» с сохранением всех путей | Около 2,90 ГБ содержимого | Возможны жёсткие ссылки для неизменяемых файлов либо общее хранилище вложений. До замены повторно проверить содержимое и убедиться, что загрузчик не перезаписывает связанные файлы на месте. Простое удаление копий может сломать ссылки. |
| Сжать закрытые биржевые CSV до сентября | Предварительно около 7,18 ГБ | Оценка по пробам первых 2 МБ из шести папок; полное сжатие может дать другой результат. Объём этих CSV — 9,37 ГБ. Сжимать по одному закрытому файлу с проверкой архива, после подготовки читателей. |
| Перенести скачанный раздел «Форумхауса» на компьютер | До 7,09 ГБ на сервере | Только после проверки полной внешней копии. Сохранить runtime/exported_threads.json и состояние загрузчика. Эта экономия включает дубликаты из строки выше, складывать их нельзя. |
| Разобрать старые временные видео и повторные дачные кадры | Примерно 0,15–0,30 ГБ | Убедиться, что временные ролики не являются единственными нужными копиями; сохранить рабочие ссылки на кадры. |

Первые два пункта дают ориентир около 1,5 ГБ без удаления заметок, видео и биржевой истории. Они не устраняют дальнейший рост сборщиков.

Совместимость сжатия уже проверена по коду: /root/trading/scripts/dash_build_bars.py выбирает trades_*.csv* и читает через pandas, но /root/trading/build_bars.py выбирает только trades_*.csv. Перед архивированием нужна проверка остальных читателей и исправление тех, которые пропускают .gz; иначе анализ незаметно потеряет часть истории. При нынешнем малом остатке места сначала требуется освободить кэш, затем обрабатывать архивы последовательно.

Для устойчивого хранения стоит определить, какая биржевая история нужна на сервере для работы, а какая — на компьютере для исследований. Конкретный срок хранения не назначен. Исходные данные «Форумхауса» можно выгружать по существующим правилам проекта, сохраняя реестр для докачки продолжений.

Для Git стоит исключить дальнейшее накопление временных результатов и журналов после проверки, что нужные результаты сохранены в проектных папках. Существующую историю не переписывать без отдельной подготовки: это затрагивает другие копии репозитория. Крупные медиа лучше хранить отдельно от заметок с явными указателями, как уже сделано для дачных кадров.

Установленные браузеры /root/.cache/ms-playwright и /home/egor/.cache/ms-playwright вместе занимают около 1,23 ГБ, но это исполняемые компоненты загрузчика и direct_web, а не только временный кэш. Удалять их как мусор нельзя. Окружения .venv/venv, данные Codex, секреты, настройки и файлы подкачки также не отнесены к обычной очистке.

**Основания и границы проверки**

Размеры измерены через df и рекурсивный du от / в пределах основного раздела с правами root. Крупные деревья разобраны до файлов; в двух наборах изображений выполнено сравнение SHA-256. Назначение служб сверено по systemd, открытым файлам процессов, расписаниям и исходному коду сборщиков. Секреты в отчёт не включены. Внешние резервные копии и содержимое других компьютеров не проверялись; старое имя папки или дата файла сами по себе не означают, что данные лишние.
