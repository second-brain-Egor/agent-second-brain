## 2026-04-09 — Сетевой сбой после WireGuard
- Пользователь не хочет пересказа содержимого фото экрана; нужен сразу вывод и действие
- После запуска PowerShell-скрипта переключения WireGuard интернет на Windows пропал
- По снимку `ipconfig /all`: Ethernet получил нормальный IPv4 `192.168.1.56`, шлюз `192.168.1.1` и DNS от роутера, значит локальная сеть жива
- Наиболее вероятная причина обрыва: активный WireGuard-туннель/маршрут после скрипта перехватывает трафик или оставляет kill-switch
- Для аварийных инструкций на Windows нужны короткие команды, которые можно ввести вручную без копирования

## 2026-04-29 — Обработка нескольких фото
- Если пользователь присылает несколько фото, их нужно рассматривать как одну пачку контекста и не терять отдельные изображения
- Фото без явной задачи не нужно сразу транскрибировать, переводить или описывать в чат; сначала нужно спросить, что с ними сделать
- Пользователь болезненно реагирует на повторы; если замечание уже прозвучало, не повторять ту же мысль в следующих сообщениях без новой причины

## 2026-04-29 — Напоминания
- Если пользователь указал конкретное время напоминания, нужен один сигнал ровно в это время, без повторов каждые 20-30 минут и без автоматического дожима

## 2026-04-24 — Правило явного запуска
- Любые действия, проверки, изменения и запуск агентов нужно делать только после явного разрешения пользователя и только по команде `делай`
- По умолчанию рабочий режим — обсуждение и планирование; запрос на отчёт означает подготовить отчёт, а не начинать уборку или изменения
- Если пользователь прямо обозначил режим планирования, нельзя вносить изменения в материалы, файлы, проекты, конфиги, Todoist или другие системы. Разрешён только просмотр, анализ и предложение; перед внесением нужно спросить разрешение на конкретное действие.
