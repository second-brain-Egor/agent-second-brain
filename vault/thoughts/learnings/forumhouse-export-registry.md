# Forumhouse: авто-реестр выгрузок и дельты (с 2026-06-11)

Канон по `ssh barriga` → `/root/forum-harvest`. Полные правила: `/root/forum-harvest/ПРАВИЛА-ВЫГРУЗКИ.md`.

## Суть

- Реестр выгруженных тем: `runtime/exported_threads.json`. Фаза `register` в конце
  каждого цикла фиксирует ВСЕ темы с диска (включая partial) со свежими счётчиками.
- Егор копирует **всю папку раздела целиком** и удаляет с сервера — ручных шагов нет.
- Раз в 8 циклов (~сутки) audit пересматривает живой форум (`--refresh-audit-every-cycles 8`):
  находит новые темы и рост существующих.
- Выросшая тема: файл на диске → докачка в файл; файл выгружен → качается **только хвост**
  в новый файл с `posts_offset` (полная перекачка не происходит никогда).
- 475 тем майского ручного импорта (999999) закрыты навсегда — нет точки возобновления.

## Как проверять «не качает ли по кругу»

1. `runtime/summary.json` → `status_counts`: `exported_pruned` — выгружено и не трогается,
   `delta_pending` — ждут докачки хвоста (это НЕ перекачка).
2. В `runtime/events.jsonl` фазы `register` и `audit` — `returncode 0`.
3. В логе sync/repair у дельт строка «качаю только хвост со стр. N».

## Связанное

- [[loading-vs-git-export]] — различение «загрузка Forumhouse» vs «git push».
- Известный фон: sync-фаза периодически падает на DDoS-Guard (антибот) — новые темы
  и дельты качаются в удачные окна. Это не ошибка реестра.
