# Ограничения выполнения запросов

Кнопка справки настраивается отдельно у каждого владельца: `SHOW_HELP_BUTTON=false`
в его `.env` скрывает «❓ Помощь», сохраняя команду `/help`. Настройка не переносится
между экземплярами при синхронизации общего кода.

Введены 19 сентября 2026 года по поручению владельца после длительного запроса,
который занял чат и многократно проверял фоновую обработку через модель.

- Обработчик обновления передаёт запрос отдельной задаче Python и сразу освобождает
  приём сообщений. Автоматическое сообщение о фоновом выполнении отключено
  по просьбе владельца; управление задачами продолжает работать.
- `стоп`, `/stop`, `/cancel` завершают активные задачи этого пользователя и снимают
  ожидающие задания документов. Голосовая команда распознаётся один раз. Доступ
  проверяется до выполнения команд управления.
- `/tasks` и «статус задачи» читают сохранённое состояние без модели и не прерывают работу.
- Обычные сообщения и уточнения не отменяют начатую работу. Они сохраняются в
  очередь своего чата и выполняются последовательно, с контекстом предыдущего ответа.
  Голосовые сохраняют место в очереди ещё до окончания распознавания. Уточнение
  обрабатывается после текущего ответа: уже запущенный CLI не получает его мгновенно.
  Ожидание очереди не вызывает модель и не расходует время выполнения следующего
  запроса. Вложения альбома принимаются независимо. «Стоп» отменяет и выполняемое,
  и ожидающие задания; позднее распознавание старого голосового не запускает работу.
  Запрос состояния проходит сразу, не снимает задания и не вызывает модель.
- По умолчанию задача ограничена **600 секундами, одним запуском CLI модели и 24
  наблюдаемыми шагами**. Ошибка чата не вызывает автоматический повтор. Остановка
  завершает процесс, его группу и найденные дочерние процессы, включая отдельные группы.
- Просьба «дай просто ссылку/путь» ограничена отдельно: 90 секунд и 8 шагов.
- Документы сохраняют прежний предел до двух попыток подготовки в общем бюджете;
  достижение ограничения не повторяется. Незавершённая подготовка после перезапуска
  требует отдельного повторного запуска. Чтение документа тоже подчиняется остановке.
- Для пакета ежедневной обработки: до 8 запусков и 96 шагов за те же 600 секунд.
  Пройденные даты сохраняются по мере выполнения, остаток остаётся необработанным.
  `PROCESS_BACKEND` выбирает исполнителя обработки, `AI_BACKEND` — диалога.
- Состояния и журналы: `vault/.session/tasks/<id>.json` и `<id>.jsonl`. Сохраняются
  исходное поручение, состояние, счётчики, последний шаг и поток событий исполнителя.
  Изменённые агентом файлы сохраняются на обычных местах. Это журнал для продолжения,
  а не обещание автоматического возобновления с произвольной строки программы.
- Ожидание завершения процесса выполняет Python без обращений к модели. Повторные
  вызовы известных инструментов ожидания ограничены двумя на задачу. В запрос
  добавлено требование не возобновлять старые поручения из истории без текущей команды.

Настройка через переменные окружения: `TASK_TIMEOUT_SECONDS`, `TASK_MAX_MODEL_CALLS`,
`TASK_MAX_STEPS`, `TASK_LOCK_WAIT_SECONDS`,
`PROCESS_MAX_MODEL_CALLS`, `PROCESS_MAX_STEPS`, `SHORT_REQUEST_TIMEOUT_SECONDS`,
`SHORT_REQUEST_MAX_STEPS`. Положительные значения обязательны;
некорректное значение заменяется безопасным значением по умолчанию.

Запуск CLI и наблюдаемый шаг не равны точному числу внутренних запросов провайдера.
Процент недельного лимита эти счётчики не измеряют. Для Codex учитываются события
[`codex exec --json`](https://developers.openai.com/codex/noninteractive), для Claude —
сообщения потока `stream-json`. Внутри одного шага расход дополнительно ограничен
общим временем. Отдельные внешние службы, ранее запущенные через systemd, этим
контроллером автоматически не останавливаются.

Проверка: `uv run pytest -q tests`. Тесты используют подставные исполнители и реальные
локальные дочерние процессы, без запросов к платным моделям и без отправки сообщений
пользователям. При обновлении каждого экземпляра сохраняется резервная копия;
личные хранилища и параметры доступа между экземплярами не переносятся.

### Сохранение очереди — 19 сентября 2026

Личные сообщения сохраняются в `vault/.session/request-inbox.sqlite3` до распознавания голоса и возврата управления приёму сообщений. При запуске ожидающие сообщения передаются обычному диспетчеру в порядке поступления, с повторной проверкой доступа. Сохраняются исходное сообщение Telegram, вложения и готовая расшифровка. Выполненные, начатые, остановленные и завершившиеся ошибкой поручения автоматически не повторяются. При штатном выключении ожидающие сообщения остаются в очереди; «стоп» помечает их остановленными на диске. Старые поручения, для которых полное сообщение ранее не сохранялось, восстановить таким способом нельзя.

Первое включение ожидает завершения текущих сообщений старой версии. При проверке очереди учитывается процесс Python из проекта, а не только MainPID службы (это оболочка flock).
