# Документы в боте

## Хранение

Бот Ирины работает с `/home/irina/agent-second-brain/vault`.
При загрузке сначала запрашивается выбор пользователя:

- `PDF/<название>-<идентификатор>/` для PDF;
- `Документы/<название>-<идентификатор>/` для остальных форматов;
- `projects/<выбранный проект>/Документы/<название>-<идентификатор>/` внутри проекта.

В папке документа находятся оригинал, `текст.txt`, контрольная сумма текста,
`Описание.md`, `.document.json` и `Результаты/<идентификатор задания>/`.
В результатах сохраняются итоговый файл и `содержание.json`.

До выбора папки новая загрузка находится в `.documents/incoming/`.
Повторные загрузки с одинаковой контрольной суммой в одном чате используют
зарегистрированный оригинал. Старый файл из `attachments/` остаётся на месте
до выбора папки, затем переносится. Повторно загружать его не нужно.

Состояние выбора, привязка сообщений и очередь находятся в
`.documents/state.sqlite3`. Общая память содержит только название и путь;
папки документов исключены из индекса Markdown. Полный текст не добавляется
в сессию и ежедневные записи. Временные изображения OCR удаляются автоматически.
Не выбранные пользователем документы автоматически не удаляются.

## Обработка и восстановление

Подпись к файлу, отдельный текст и расшифрованное голосовое сообщение направляются
в одну очередь. До выбора папки обработка не начинается. Модель получает
извлечённый текст и возвращает структуру результата; файл создаётся и проверяется
программно. Большой текст передаётся через локальный файл без молчаливого обрезания.

Для презентаций без указанного формата бот спрашивает: «В каком формате
подготовить презентацию — PowerPoint (.pptx) или PDF?» Ответ принимается кнопкой,
текстом или расшифрованным голосом. Если формат уже указан, вопрос пропускается.
Исходное задание и ожидаемый выбор сохраняются в таблице `presentation_choices`
той же базы `.documents/state.sqlite3`. До выбора генерация не запускается.
Выбор и постановка задания по документу в очередь записываются одной транзакцией;
повторное нажатие не создаёт повторное задание. Название PDF-источника само по себе
не задаёт формат презентации. Вопрос о папке сохраняется отдельно и задаётся первым.
Для презентаций без загруженного источника после выбора продолжается обычный диалог
с исходным заданием и явно указанным форматом результата.

Чтение документа, распознавание страниц и генерация не ограничены по времени. При временной ошибке
или некорректном результате модели разрешена одна повторная попытка.
После перезапуска незавершённая обработка восстанавливается в пределах двух попыток.

У Telegram нет ключа идемпотентности для отправки файла. Если отправка прервалась
и подтверждение не получено, автоматической пересылки нет: пользователю доступна
кнопка повторной отправки. Это предотвращает автоматические дубликаты, но не
означает гарантированную доставку при обрыве связи. Подтверждённая отправка
сохраняет номер сообщения в базе и повторно не выполняется.

## Зависимости и проверка

Системные программы: `pdfinfo`, `pdftotext`, `pdftoppm` из `poppler-utils`,
`tesseract-ocr`, языковые пакеты `rus` и `eng`, шрифт DejaVu Sans.
Библиотеки создания файлов закреплены в `pyproject.toml` и `uv.lock`.
Для визуальной проверки PPTX использован LibreOffice; для работы бота он не обязателен.

Основная проверка: `uv run pytest tests -q`.
Проверка цепочки документов: `uv run pytest tests/test_document_pipeline.py -q`.
